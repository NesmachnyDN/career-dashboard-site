Career Operations Platform

Публичный architecture case study. Все данные в runnable demo синтетические.

Проблема

Карьерный процесс включает discovery, оценку fit, взаимодействия, контент, аналитику и последующие действия. Архитектурная задача — не смешивать историю наблюдений с каноническим состоянием и сохранять человеческий контроль над внешними действиями.

Архитектурная схема

Sources
→
Workflows
→
Append-only runs
→
Derived Career Center

Discovery history и canonical opportunity state разделены. Dashboard является read-only derived projection и не становится вторым источником истины.

Human-control boundary

AI: discover / assess / draft
→
Human decision
→
External action

Demo не содержит mutation controls. Отклики, сообщения и публикации всегда требуют отдельного решения человека.

Ключевые trade-offs

  • Static/GitHub-first: ниже стоимость и операционная сложность, но нет realtime mutation plane.
  • Append-only history: высокая traceability ценой более сложных derived projections.
  • Human-in-the-loop: меньше автономности, зато управляемый репутационный риск.
  • Synthetic public data plane: открытая демонстрация без использования production career data.

Privacy-by-design

Public demo собирается только из committed synthetic fixture. Перед публикацией автоматическая проверка подтверждает явный demo marker, отсутствие private runtime references и совпадений с production records.
